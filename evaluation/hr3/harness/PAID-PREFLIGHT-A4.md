# Paid A-4 preflight

`runner.mjs` calls `verifyPaidPreflight` for every real transport before creating a journal or dispatching. Accounting alone cannot authorize execution. Fake transports exercise the offline pipeline and never produce paid readiness.

The default record is `reports/paid-preflight-a4.json`. The primary supplies it after the passing non-author audit and freeze. There is deliberately no command that creates this record or a review attestation. The validator's test-only synthetic interchanges are discarded and are not approval evidence. Production validation explicitly rejects their testOnly review marker; the complete synthetic interchange must reach that rejection boundary rather than return readiness.

The record has `version: hr3-paid-preflight-a4-v2, stage: pilot`, `scope: one_uncalibrated_60_family_pilot`, `requirements` exactly matching the applicable ID/clause arrays returned by requirementsForStage(stage) in paid-requirements-a4.mjs, and `evidence` mapping each ID to `{path, sha256}`. Every path is repository-relative. Each evidence object has status PASS, a nonempty `sources` map of exact file digests, and `runtimeClosureSHA256` for the complete active implementation. Evidence and sources are re-read at run entry. Frozen bytes and the current independently derived closure must agree.

The normal output/request/privacy certificates can be referenced directly. certification-bundle-a4.mjs emits the observed embedding, conformance, allocation and semantic-inventory certificates after the ordered offline checks. It never emits review, supervision, resource, analysis or paid-readiness evidence. An accounting evidence wrapper binds the exact reconciled budget and supplemental carry. `freshRun` is the primary's one-run plan and must name the same empty output directory passed to the runner.

The review object additionally requires `suppliedBy: primary`, `nonAuthor: true`, a recorded reviewer, `decision: acceptable_for_paid_pilot`, amendments `[A-4, A-4.1, A-4.2, A-1.1]`, the exact `freezeSHA256`, `closureSHA256`, and `evidenceBindings` for every other requirement. Code validates these assertions and hashes; it cannot create an independent review or establish a human identity.

Analysis evidence must pin its implementation and a result manifest. The manifest contains exactly the prespecified 60 power cells and 12 allocation/outcome coverage cells, unchanged workloads and design, actual coverage/decision metrics and Monte Carlo uncertainty, boundary supplements, runtime binding and source hashes. Missing, stale or reduced results block the gate. The analysis implementation/results and measured resource records were not found in this checkout during this repair; a reduced demonstration is not substituted for the required rerun.

A-1 waives calibration ordering and pilot sampling CIs only. It does not waive these non-adjudication requirements. Calibration v2 and calibrated development/accuracy reporting remain separate future gates. A passing offline verifier is not permission for paid work.


The recheck adds a dependency check before runner output/journal creation. The only accepted installations are `adapters/mcp/node_modules` and `adapters/openai/node_modules`. Omitting the CLI options selects these exact defaults; alternate installations and symlink aliases are rejected before installing a resolver or importing a dependency. Runtime package resolution must remain within the bound installations, and the freeze records the same dependency configuration. No real-CLI modification is required.

New journals use `hr3-ledger-a4-v2` and a separately durable `ledger.jsonl.head.json`. Each successful append fsyncs the journal before atomically replacing and fsyncing the checkpoint. Journal loss, empty content, configuration changes, prefix rollback and checkpoint disagreement fail closed before reservation/dispatch; the accepted position is also retained in memory. A crash between journal and checkpoint persistence requires explicit reconciliation and never authorizes replay. Existing historical journals/carry manifests remain unchanged. Completed/stopped artifact manifests include and bind the checkpoint.


The second recheck makes `read()`/`snapshot()` coherent, locked, read-only observations. They report corruption or a busy lock without writing a blocked checkpoint. Writer transactions acquire the same lock and revalidate on-disk state. Persistent rejection requires owned writer-lock authority and unchanged checkpoint bytes; it preserves the newest cursor instead of a stale accepted head. Dispatch checks use writer transactions; watchdog observations remain read-only. Busy monitoring does not poison healthy accounting, while the five-minute stall stop remains enforced. Existing checkpoint/journal formats and all numerical limits are unchanged.


The third recheck adds bounded asynchronous accounting contention handling: 5 ms initial backoff, doubling to 100 ms, with a 15,000 ms total deadline per accounting operation (configuration may only use 1–30,000 ms). This does not change provider retry allowances, caps or the five-minute progress deadline. Every reserve, settlement, failure record, stop and authoritative check retries only its accounting operation. Watchdog reads report busy rather than queue; distinct writer-intent files make observers yield across processes until waiting writers finish. Intents never alter the journal/checkpoint; abandoned intents require operator cleanup and do not prevent writers from taking the accounting lock.

Before any post-reply accounting, `ledger.jsonl.responses/<hash-of-attempt-id>.json` atomically fsyncs the complete JSON reply plus attempt/logical identity, operation and request-body hash, mode 0600. Successful settlement removes and fsyncs that entry. A failed accounting path keeps it. Deadline exhaustion independently fsyncs `ledger.jsonl.accounting-stop.json`, retains all reservation exposure and latches the transport stop. This separate stop never rewrites a checkpoint or authorizes dispatch: a resumed ledger includes it in its stopped state and every reserve checks that state. Reconciliation is explicit; the harness neither releases reservations nor replays requests. Failure/summary artifacts bind the retained files and mark any last coherent accounting snapshot as stale while the journal lock remains unavailable. A storage failure is fatal; no provider replay is attempted.

Watchdog stop recording is a separate bounded writer operation. It aborts a stalled dispatch immediately, while the runner awaits any pending stop accounting before publishing failure/summary manifests. Reply-directory creation is also anchored by fsync of its parent before writing the response. Earlier monitoring observations remain read-only; no background accounting write is left running after artifact publication.

Settlement retries recheck both the supervision stop and the elapsed progress deadline. A lock wait crossing five minutes cannot settle usage or reset progress; it retains the received response for reconciliation and stops without another provider dispatch.


The fourth recheck replaces anonymous writer intents with `v2.pid.starttime.bootId.pidNamespace.nonce` markers, published as one exclusive, empty mode-0600 file in the existing mode-0700 intent directory. The complete identity is in the atomically created filename, so a crash during publication cannot leave an identity-free partial payload. `/proc` is an operating-system interface, not an embedded workspace path. Linux starttime parsing handles spaces and parentheses in comm; numeric identities are canonical and the nonce uses crypto.randomUUID.

Ordinary observations first classify intents without modifying them, then acquire the existing accounting lock and reclassify/revalidate before removing a dead owner's marker. Reclamation requires matching boot and PID-namespace scope plus either an observed different process starttime (PID reuse) or missing proc data corroborated by ESRCH. Removal checks the unchanged file identity and repeats the liveness proof under the lock. Active identities, unreadable/malformed/replaced entries and unprovable/foreign scope remain blocking and are reported through ledger errors and minute supervision diagnostics. Missing identity on non-Linux or restricted proc mounts is a conservative fallback, with no time-based expiry. Anonymous legacy markers cannot be attributed safely and remain unknown for explicit operator reconciliation. Existing stale accounting locks still require reconciliation; this change reclaims abandoned intent markers, not accounting locks.

Provider retry rules, the 15-second accounting bound, the five-minute stop, reservation/response retention, caps, schemas and the paid-primary-attestation gate are unchanged. Independent-process tests use regular-file stdio and atomic test-only mailboxes; each mailbox operation allows 60 seconds, each process test 180 seconds, and earlier transient-contention tests allow 20 seconds. No production timing limit is raised.
