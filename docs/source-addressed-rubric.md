# Frozen source-addressed development rubric

Eight new texts adapted from known failure categories, not a blind holdout.
Compare original basis and source-addressed-v1, three existing models, one
attempt per slot. Maximum48slots/96HTTP/US$2.048 conservative reservations in
the unchanged aggregate50ledger. Same6,000 input/1,024 output token ceilings;
numbered-source overhead counts. Retain rejected, omitted and failed outcomes,
with no retry or default promotion. Prompt/schema/addressing/dual-role changes
are bundled, so individual causal contributions cannot be isolated.

Manually admit the same canonical source receipts for each case/arm/model.
No extraction, MOC retrieval, final answer or actual user task is measured.
Keep structural completion, source fidelity, role/link correctness, required
missing relationships, useful scope/time/commitment context, latency and cost
separate. Exact addresses are not semantic proof. Unknown fields may remain null.
An irrelevant or insufficient selected span is not made correct by its address.
Any extra unlinked negative statement labelled as an adopted decision is a role
error; empty outputs cannot satisfy positive cases. More links are not better.

1. watch-battery: separate seven-day battery and water-resistance reasons for
   the original choice. Two-day battery challenges only battery. Do not invent a
   replacement or challenge continued water resistance/swimming.
2. museum-opening: old morning choice supported by old09:00 opening; new13:00
   opening challenges its present applicability AND supports explicitly adopted
   afternoon choice. The historical opening time remains historically valid.
   Either correctly duplicated roles in original mode or one explicit dual-role
   unit in addressed mode may express these relationships. Score semantics, not
   the preferred unit count. Missing new support is an omission, not success.
3. planner-owners: Jo/Aspen/weekly and user/Hazel/offline remain separate. Only
   connection-required update challenges offline. Jo's unchanged choice is not a
   new user's choice or a challenge to the weekly view.
4. temporary-office: usual home/quiet and temporary office/renovation-noise are
   separate scoped decisions/reasons. Do not infer a permanent office choice or
   invalidate the normal routine beyond the explicitly temporary condition.
5. old-encryption-report: April20 choice supported by April18 capability. March3
   negative report is historical, not a current challenge. Today's encrypted
   export is compatible confirmation, not a reason to challenge current support.
6. unadopted-vpn-zh: no adopted choice or purchase authority. Advice, consideration
   and requested verification are not decisions. Empty units/links appropriate.
7. charger-reaffirmed: retain source-supported charging reason without challenge.
   A valid confirmation-premise support is semantically acceptable; distinguish
   original-source coverage from false links if that alternative is selected.
8. corrected-belief-zh: initial choice supported by explicitly attributed belief
   about PDF export, not an objective fact. Later correction challenges that
   belief-based reason. No adopted replacement or execution permission follows.

Keep all original receipts and warm/cold nonpersistent state checks, but do not
count these as semantic wins. Judgments remain nonblind agent review with full
sources. Any future tuning/replay uses development evidence, never a fresh score.
Broader held-out and installed full capture/restart/recall work remain required.
