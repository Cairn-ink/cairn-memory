# Is the current memory architecture at a local optimum?

There is a risk, not evidence of an unavoidable ceiling. The goal is a reliable,
lightweight memory layer, not preserving MOC or any particular implementation.

## Reproduce the present boundary

Run `npm run demo:architecture-boundaries` on Node 22.16 or 24. It makes no
provider calls, reads no credentials and opens no database. `npm test` includes
the diagnostic's regression tests. These fixtures are hand-authored semantic
counterexamples, not fresh model outputs, a holdout or user success rates.

The real source-basis compiler accepts both the author-labelled supported and
unsupported proposal in four paired examples: swapped actors' reasons, swapped
normal/temporary reasons, a late historical report challenging newer state, and
confirmation treated as a challenge. Quotes and sources are identical within
each pair. All accepted units and links remain **model-proposed**, not verified.
The fabricated-quote control is rejected. This is the intended compiler trust
boundary, not a newly discovered authorization bypass.

The six-unit two-chain control fits; a nine-distinct-unit three-chain encoding
does not. Each of those three chains compiles in isolation. This demonstrates a
per-proposal capacity bound, not a universal limit of MOC, proof that no compact
encoding exists, or a reason to remove resource bounds. Decomposition would need
its own cross-batch consistency and coverage contract.

The diagnostics currently record four unsupported accepted proposals. Tests
passing mean the observations reproduce, **not** that those errors are desirable
or memory quality improved. If semantics or the schema changes, reassess and
version these diagnostic expectations instead of protecting the old failures.

## What the evidence separates

- **Representation:** exact source spans and typed links preserve inspectability,
  but the basis schema has no structured actor/time/scope applicability assessment.
  Those details can remain in source text; their presence does not validate a link.
- **Interpretation:** the [real-model comparison](source-basis-comparison-results.md)
  supplied exact receipts without retrieval and still found semantic errors.
  MOC selection cannot explain those particular failures.
- **Retrieval:** the [source-scan experiment](source-scan-ablation-results.md)
  found source-selection misses. The bounded complete-map option covers small
  sets, not arbitrary histories. Selection and later ranking are separate loss
  points; fixing source interpretation does not establish retrieval coverage.
- **Whole loop:** neither these compiler probes nor the manually admitted basis
  study proves automatic capture, next-day retrieval and final explanations work
  together. Existing lifecycle checks are not substitutes for this evidence.

## Next implementation and falsification sequence

1. **Applicability experiment, not another truth flag.** Prototype source-anchored
   actor, event time versus receipt time, conditions and adoption evidence, with
   an explicit unresolved outcome. Compare with current basis proposals on the
   same complete sources and matched model/input/output budgets. Source-backed
   fields remain interpretations; a second pass must not certify itself.
2. **Retrieval control.** Compare existing MOC selection with bounded direct-source
   and a lexical/hybrid candidate baseline. For corpora fitting context, direct
   source is a reference, not the scalable product design. At larger sizes enforce
   equal context budgets, record excluded/truncated evidence and scale history
   length. Include paraphrases, unrelated decoys and updates filed elsewhere.
3. **Installed full loop.** Freeze fresh conversations and expected source-backed
   answers before paid calls. Capture without manual admission, restart, then ask
   current-state, historical-reason and changed-basis questions. Measure source
   preservation, retrieval, unsupported conclusions, useful correct answers,
   abstention, latency and cumulative cost separately. Run an oracle-source arm
   to localize losses, not as the deployed result. Retain all failed attempts.

Use disjoint development and held-out cases; do not tune prompts on held-out
failures and continue calling them held out. Freeze the rubric, practical quality
and cost thresholds, source version and bounded operator before model spending.
No new paid run is included in this diagnostic delivery.

If complete-source interpretation is the bottleneck, improve applicability or
abstention rather than adding MOC traversal. If MOC loses required evidence to a
matched-budget baseline, revise or replace candidate selection. If added
structure does not improve useful, source-supported answers on fresh cases at
acceptable cost, simplify it. Promoting automatic state changes or advertising a
reliable memory loop remains gated on that evidence, not unit-test counts.
