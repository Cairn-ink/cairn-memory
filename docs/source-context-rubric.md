# Frozen development ablation rubric

These are new synthetic texts adapting known failure categories. They are not
a blind holdout or real-user evaluation. Both arms use the same original
canonical receipts, selected manually. Prompt/schema/representation change
together; this ablation does not isolate their individual causal contributions.

Eight cases, three existing models, two arms: original basis and source-context.
Maximum 48 slots, 96 HTTP calls, US$2.048 conservative reservation inside the
unchanged US$50 ledger. Same 6,000 input / 1,024 output token ceilings; context
overhead counts. One attempt per slot, retain rejected/omitted/failed results.
No fallback or default promotion. No automatic capture, retrieval or answer task.

Review every result against its complete canonical source, not quote matching
alone. Separately record mechanical completion, wrong links/roles, required
missing links, context citations preserving or losing qualifiers, unchanged
sources, cold state, elapsed time and costs. Empty outputs cannot satisfy positive
cases. Extra unlinked context is not automatically a semantic error or coverage.
No composite accuracy percentage from these eight author-scored examples.

Expected source relationships:

1. backup-region: original choice supported by Finland and two-hour restoration
   separately. Canada challenges only the Finland premise. No adopted replacement.
2. training-stage-zh: two different-stage decisions, each with its own reason.
   Acquiring qualifications does not challenge the still-valid no-prerequisite
   property of the beginner class. No invented cross-stage reason or contradiction.
3. device-owners: Lee/Quartz/read-aloud and user/Linen/matte must remain separate.
   Removed read-aloud challenges only Lee's reason; matte confirmation is not a
   challenge, nor has Lee adopted a replacement.
4. temporary-delivery: regular Juniper choice supported by crates; Friday-only
   Marigold choice supported by Juniper's one-day unavailability. This is not a
   challenge to the regular crate reason. Do not swap supporting reasons.
5. old-inspection: booking supported by post-installation step-free access. Old
   pre-ramp report is not a current challenge. Do not use old inaccessibility as
   the reason for the booking. Today's visit is compatible confirmation.
6. consideration-zh: no adopted decision. Assistant advice and user's consideration
   must not become adoption, a decision chain or purchase authorization. Empty
   units/links are appropriate for this decision-focused API.
7. winter-rating: selected heater supported by operating temperature; independent
   confirmation is not a challenge. At least the original support must remain.
8. explicit-plan-change: old choice had old meeting-time support; new choice has
   new meeting-time support. Updated start challenges the old premise's current
   applicability without denying its historical truth. New choice is explicitly
   adopted, not an invented substitution. Do not merely abstain from all change.

Context field quotes remain proposed, even when valid; null is unresolved. Exact
citations are not proof of semantic field assignment or relation compatibility.
Continue to keep mode opt-in regardless of these small-sample outcomes. A broader
held-out and full-loop comparison is required before any reliability claim.
