# Synthetic migration-memory lifecycle diagnostic

Run `node --test core/test/migration-lifecycle.test.mjs` on
Node 22.16 or 24. It uses only a fresh temporary SQLite database, public
`openMemoryCore` calls, injected deterministic models and a fresh reader process.
Set `CAIRN_MIGRATION_TRACE=1` to emit the synthetic write/read trace through the
test runner's diagnostics. No provider, key, migration/operational command, production
database, or paid call is involved.

The frozen timeline separates **report/event date** from **arrival index**. The
late-arriving report describes use on January 15, before the February 1
retirement report. Those dates are retained in source text and test metadata;
they are not a structured temporal claim model or proof of actual chronology.
The unrelated Staging backup rule is a control. Writer callbacks explicitly
script extraction, qualification, classification and proposed rationale. The
cold reader receives only path, ordinary namespace/query/config and its generic
select-all/rank-all test adapter. It has no fixture answer, transcript, or
writer closure. `sourceSnapshot` supplies an independent complete-current-source
diagnostic for this six-record set; source completeness is not semantic quality.
The injected `countTokens: () => 1` is only a test convention: these cases do
not validate a real tokenizer, context budget or large-map search behavior.

Observed contract in the positive-control script: six source-qualified records
remain current, each with a retained receipt; classification and rationale
complete, and the fresh process receives all six receipts. The scripted
support/challenge path makes the conditional restriction's rationale
`reconfirmation-suggested`, not revoked or replaced. The unconfirmed hypothesis
has `unknown` commitment. The retirement source explicitly leaves other
dependencies unassessed and does not authorize removal. A source-qualified
ordered capture returns `qualification_requires_identity` with zero retirements
for each batch. This is the documented, deterministic boundary: automatic
same-slot binding and retirement are not provided. It is not a test failure
that the prior v1 evidence remains active, but it is a failure of any claimed
automatic current-state update contract.
The `commitment` value is a model-proposed description of an utterance, not a
verification or present-day truth flag. The unrelated Staging rule retains its
own `Staging` scope and `backup retention` property after a cold read.

In the adversarial script, the model labels the explicitly unconfirmed
hypothesis `adopted` and proposes a challenge from the pre-retirement report as
if it challenged the current premise. Both structurally valid interpretations
persist with their original receipts visible. The core validates source binding
and revisions, not entailment or temporal applicability. The tests intentionally
do not generate an answer or call a scripted answer observed agent behavior.
`rationale-evidence` omits interpreted memory bodies/qualification by design;
the reader separately uses `list/get(includeQualification:true)` to inspect
those fields. This explicit mode should not be mistaken for the MCP default.

The separate ML4 case uses public placement to create a title sourced to the
confirmed premise's exact revision. It then re-runs public rationale review at
the post-placement revisions, verifies the proposed support/challenge path,
and corrects that premise through public `correct`. A new process sees the old
MOC's classification title as `null`, no visible recall MOC for it, and the
conditional restriction's rationale as `unassessed` with no incident edges.
The corrected source has a new revision/receipt; the Staging rule's revision and
qualification are unchanged. Correction is distinct from merely capturing a
new conflicting report. This checks invalidation, not whether the correction
itself proves field removal safe.

This diagnostic does not establish extraction, temporal reasoning, premise
dependency resolution, field-removal safety, general recall relevance, or real
model reliability. The cold reader's select-all/rank-all callbacks are a
scripted integration control, not observed natural model relevance or an answer.
