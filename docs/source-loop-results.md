# Installed source loop: sources survived, interpretation remains incomplete

This run exercised actual model capture → store close/keyless reopen → MOC
source-evidence recall → original decision-basis review. It did not manually
admit ideal memories. All eight required source messages were retained and
returned by MOC across four small cases. That is useful pipeline evidence, not
proof of reliable answers or a reason to promote experimental basis modes.

See the [frozen fixture](../evaluation/live/source-loop-fixture.json),
[rubric](source-loop-rubric.md), [driver boundaries](source-loop-controls.md),
and [all public outcomes](../evaluations/results/source-loop-controls-v1.json).

## What actually ran

Four fresh synthetic development cases adapted from known failure categories,
two capture windows per case, no blind holdout. The installed shared core used
`source-bound-v2` qualification; capture/select/rank used
`gpt-4.1-mini-2025-04-14`, and all basis controls used `gpt-5.6-sol` with the original
basis mode. No source-addressed mode or default was promoted.

Each case compared MOC-selected refs, simple lexical source matches, and all
captured refs. Every control reviewed the same underlying store without writes.
There were three captured memories per case, well below broad retrieval-scale
claims. Classification created L1 groups and filed subsequent updates into them;
this was real MOC selection/ranking, not a downloaded large-scale benchmark.

Eight captures succeeded, all classifications reported applied, no retained
source window reported truncation, and all warm/cold snapshots matched. Read-only
snapshot checks also matched. Required-source coverage was 2/2 per case for
capture, actual recall receipts and all three controls. Source IDs measure
presence, not semantic correctness. Chinese punctuation was normalized by the
core; anchors match canonical retained receipts, not byte-identical input text.

Eleven of twelve basis outputs compiled; the reading lexical output was rejected.
All four case-level statuses are nevertheless `observed`: this means diagnostic
execution, not successful memory tasks. No retries, replacement cases or hidden
rescue of missing refs occurred.

A two-day-scoped noise challenge in reading is permissible under the rubric;
its omission alone is not evidence of a false permanent conclusion. The required
temporary support omission in MOC and original-role rejection in lexical are
distinct findings. In pickup, “Starting next week” is retained: the update is not
already effective today, and old18:00 validity is not falsely challenged.

Select excluded distractions in Rill, pickup and reading; rank kept both relevant
refs. Journal rank dropped the separate non-adoption memory, but not its source
evidence: the retained cloud-update receipt contains the same refusal language.
Each memory has one receipt here, so basis ref expansion did not secretly restore
missing MOC evidence. Reading lexical and oracle basis requests were byte-identical
yet outputs differed. Their rejection/improvement cannot be attributed to retrieval.

Captured summaries are less precise than source receipts. Rill's historical
reason becomes “is removable”; original pickup becomes “closes at18:00” with no
applicability value in its qualification. Receipts retain original history.
Journal's belief remains attributed, but assistant advice was not captured; this
does not establish downstream discrimination when such advice remains available.
Qualification traces are model interpretations, not independently verified facts.

## Decision and next gate

This small run does not justify replacing MOC: source evidence reached the next
stage. Nor does it prove MOC outperforms lexical retrieval generally. Missing
relationships persist with all captured sources, so enlarging retrieval alone
would not fix those examples. Original-role expressiveness and semantic omissions
remain separate from source preservation.

Keep source-backed, inspectable evidence as the usable foundation and basis
relationships explicitly unassessed. Do not block all product value on a perfect
internal graph, or claim a complete graph is the same as a correct user answer.
The next utility gate is downstream answers using actual recalled evidence,
compared with no-memory/simple-source controls, while checking historical versus
current/future scope, non-adoption, attribution, and unsupported additions. Only
then decide whether graph checking, role changes or retrieval changes improve the
user task enough to justify their cost. This answer gate has not run here.

Also pending: larger/deeper MOC workloads, final host answers, real MCP consumer
workflow, ordered reconciliation, longer maintenance histories, blind cases and
real-user validation. This is not a product-wide reliability or answer-accuracy
score, and no publication/deployment/default change is included.
