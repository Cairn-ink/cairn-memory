# Actual-core decision-evolution integration packet

## Observable contract

- DEI1. A reusable offline runner accepts a source-only fixture and an injected model factory. It sends each attributed event through `openMemoryCore.capture` in ingestion order, with one fresh synthetic SQLite database and namespace per case. It does not call `admit`, inject graph edges, force memory IDs, or send rubric fields to any model method. Event occurrence and ingestion dates are preserved as **untrusted text** in one visible source-message encoding; no capture timestamp API is implied.
- DEI2. Every capture result, failure, retained memory reference, and receipt is traced. Receipt inspection follows the core's bounded cursor through exhaustion and globally deduplicates repeated views of a shared memory. Source event IDs come from the actual stored receipt's event ID and must also match its canonical retained text; read arms map actual receipt IDs back to that inspected index. A failed or empty capture remains in the denominator and is not retried or excluded. Receipt omission and pagination failures are explicit.
- DEI3. The same captured evidence is queried through current `recall` with `source-evidence`, optionally `rationale-evidence`, and `sourceSnapshot`. The runner records evidence IDs, stage status/errors, source coverage, and absent receipts separately for each arm. A missing model-proposed rationale link is unassessed/not linked, not an inferred graph success. No arm is scored as semantic quality by scripted answers.
- DEI4. Offline scripted-model tests establish capture-to-storage-to-recall plumbing, including a deliberately root-only selector while the full-source read retains the update, no default relationship creation, late-ingested older minutes remaining identifiable, tentative source text preservation, cold reopen, forgetting, and namespace isolation. They do not claim decision-state accuracy. Both 22.16 and 24 core suites and relevant store/capture/recall demos are gates.

## Boundaries and interpretation

The fixture's `occurredAt`, `ingestedAt`, and actor are source claims. Encoding is `[Event <id> | actor: <actor> | occurred: <YYYY-MM-DD> | ingested: <YYYY-MM-DD>] <text>` on one line in a single `user` message per event. Events are submitted in fixture order; the runner does not sort on either claimed date or treat these as authenticated timestamps or human identity. Synthetic event IDs are used only for deterministic capture keys and report mapping; private client/session identifiers do not reach model inputs. One submitted event can produce zero or more memories; mappings are many-to-many and an event is covered only if the actual stored receipt has that event ID and exactly matches the core's canonical bounded source text (NFKC, redaction and whitespace normalization) for the encoded event. A text match alone does not establish provenance. The runner preflights every encoded message against the core's 4,000-unit canonical input limit and rejects invalid inputs before any case writes. It separately lists `truncatedSourceIds` and sets `incompleteCapture` when any canonical encoded message exceeds the 800-unit receipt window, even if the stored excerpt can be mapped back to its source ID. No semantic entailment follows from receipt coverage.

The three arms share a database but may differ in selected evidence. Snapshot has bounded complete-current-admitted coverage, not complete history. Recall may omit evidence through navigation/selection. Rationale-evidence is an opt-in read format; without generated relationship proposals it must not be called linked decision context. Model functions are injected for offline orchestration, and no rubric or expected state enters their inputs. Production-quality claims require an independent answer model and semantic review in a separately authorized experiment. The first useful core fix should follow the observed trace, not a hard-coded fixture edge.

## Observed base limitations and next fix

This packet intentionally leaves `captureRationale` off; `includeRationale` only exercises the existing read format and reports `relationshipGeneration: not-configured`. Its empty graph means **unassessed/not linked**, not a failed semantic link detector. A separately observed ordinary-capture trace on this fixed base found a relationship-lifecycle issue: a later filing revision of an unchanged decision can clear its existing rationale proposals. The next core packet should preserve still-source-valid links across that particular placement transaction with revision guards and a regression test, while continuing to invalidate links on genuine source changes. This observation is not built into the scripted quality score and may change after that separate fix.
