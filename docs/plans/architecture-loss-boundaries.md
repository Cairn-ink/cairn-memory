## What the construction actually exercised

The pinned [store construction][construction] injects `extract`, matching each
session against fixture `scriptedExtraction` and returning its literal content
and source indices through normal indexed capture. The core really creates
receipts, admission records and guarded revisions, but no model chooses what to
remember. `classify` returns `parentIds: []`; applied classification therefore
does not demonstrate L2-to-L1 topic navigation. Date wrappers preserve synthetic
dataset-local session dates in source text, not inferred event chronology.

No `captureRationale` option or `relate` port is supplied. Neither
`reviewRationale` nor `getRationale` is called; recall uses `source-evidence`,
not `rationale-evidence`. Therefore typed relationship creation and retrieval
were not exercised. B's [canonical groups][canonical] are request-local receipt
membership proposals compiled to selected whole cards, not persisted
`supports-decision` or `challenges-premise` edges. They cannot establish tested
causal relationships, adoption or current applicability.

The [runner][runner] opens the same prepared stores for each arm and uses bounded
source scan with limit six. Its complete-map checks bypass model `select` and
feed the full bounded candidate set to rank. A ranks refs; B ranks receipt
groups, compiled to refs. Both assemble whole-card source-only units and use the
same answer packer. [Assembly][assembly] rereads core receipts and verifies roles
and source bindings before packing. Generated memory interpretations, MOC edges
and typed rationale are not the answer evidence consumed here. The first
requests establish delivery; only original judgments establish observed use.

On main, stored [MOC organization](../moc-placement.md) is L2 broad groups → L1
topics → memory references. [Default recall](../fetch-recall.md#recall-over-authorized-namespaces)
uses bounded literal candidates; private pages omit group headers and edges.
Full hierarchical routing is an open boundary. This cohort's flat, small complete
scan cannot show that MOC routing would fix its delivered-evidence failures.

The following mapping is against the recorded main base. Experimental canonical
grouping above is separate; the architecture's Raw/Memory/Card roles are future
design responsibilities, not three implemented storage tiers or a unified Card API.

| Required manifest concept | Present contract and guard | Boundary for a fresh probe |
| --- | --- | --- |
| Canonical identity/version | Memory `id`/`revision`; exact namespace; [fetch](../fetch-recall.md) rejects stale, missing, foreign and forgotten refs, then revalidates current reads. | Bind every candidate, selected record and output to these refs; an index hit or old snapshot is not answer authority. |
| Source identity/digest/span/lineage | Attached receipt ID and client/session/event correlation; [qualification](../claim-qualification.md#shape-and-source-binding) stores core-resolved receipt SHA-256 plus exact UTF-16 span and fields, with memory content digest/bound revision. | Receipts have **no independent revision**. Preserve receipt identity/digest/span where supported; do not invent a source version or a full raw archive. Digests validate binding, not meaning. |
| Source author, claimant, subject, authority | Receipt role is submitted `user`/`assistant`, not authenticated author identity. Qualification supplies subject/property/scope/applies/value and attribution; owner namespace is an access boundary. | Claimant has no independent canonical identity field in this DTO. Author, claimant and subject must remain distinct interpretations; a namespace owner is not an attributed speaker or permission grant. |
| Event time versus ingestion time | Receipt `createdAt` records ingestion; ordinary capture message fields are ID/role/content. Qualification `slot.applies` may retain source-grounded applicability; episodes separately expose event bounds/coverage. | No general typed event-time field or event-time resolver for these receipts. Source dates and unknowns must remain explicit; causal sequence/arrival order does not prove event order. Episode time is not assertion validity. |
| Proposal/adoption/unknown and lifecycle | Qualification attribution includes proposed/unknown; commitment is adopted/considered/rejected/unknown. Memory current/historical/forgotten and explicit supersession are distinct from those interpretations. | Default capture does not create qualification. Opt-in source-bound qualification still does not verify adoption or resolve identity; null/unknown cannot mean confirmed, rejected or universally applicable. |
| Typed rationale and endpoint support | [Existing rationale](../source-backed-rationale.md): `supports-decision` premise → decision; `challenges-premise` new evidence → premise. Rows bind both memory IDs/revisions, receipt IDs/digests. | Source-backed model proposals, not adjudicated dependencies. Same-memory support is allowed; challenge requires distinct memories. No new general graph is justified here. |
| Expansion/output applicability | `getRationale` returns root, incoming supports/direct challenges and challenges to supports, bounded to 6 memories/10 edges/24000 serialized UTF-16 units; current revision/source/namespace guards and invalidation apply. | Coverage is linked-evidence-only. Any challenge gives `reconfirmation-suggested`, otherwise unassessed; neither cancels A nor adopts B. Record included/omitted/unknown evidence and truncation separately. |

Corrections, forgetting, receipt changes and material revisions invalidate
incident rationale links; guarded filing-only revisions can rebind unchanged
sources. [Opt-in capture rationale](../automatic-rationale-loop.md) already runs
bounded discovery/review after admission and reports reviewed/failed/not-run
separately; `reviewed` may mean zero edges. `rationale-evidence` consumption is
also opt-in and current-only. These present mechanisms have not established
semantic reliability. A new experiment should reuse them before proposing
schema, vectors, external databases, raw search or Card queries.
Configuration is a real boundary: `captureRationale: 'source-bound-v1'` requires
`captureQualification: 'source-bound-v2'`. It cannot be combined with the old
experiment's `captureSourcePolicy: 'indexed-evidence-v1'` (or indexed-windows).
A fresh audit must use the supported normal-capture configuration, not append a
flag to that experimental runner and call the result a one-factor replication.

### Fresh event/state case and six planned slots (definitions only)

Author one new synthetic decision, source vocabulary and independent new-session
question, with no reused RQ/CQ/BQ text or expected answers. Session one records
adoption of A because its quoted price is within an explicit budget, preserving
subject/scope/event date. A later permitted capture supplies a dated quote over
that budget for the same subject/scope; a separate suggestion proposes B without
adoption. A fresh answer session has only the fixed authorized memory readback,
not the writing conversation. Normal configured model extraction/qualification
and enabled automatic rationale must create any artifacts counted as semantic
success; handcrafted/oracle edges are mechanics checks only.

Freeze source facts before treatment. Expected source-grounded qualification is
that A needs reconfirmation and B remains proposed; A's historical rationale
remains inspectable. A proposed challenge alone warrants only the API's
`reconfirmation-suggested`, never a confirmed invalid premise or adopted B.

The six slots below are future fresh scenario definitions, not authored source
text, gold artifacts or scores. Both positive and known-answer controls are
required: always answering reconfirmation/unknown must fail.

| Planned slot | Required observation / red-capable control |
| --- | --- |
| 1. Same-scope quote crosses A's explicit budget; B merely proposed | Recognize the supported premise change and need to reconfirm A; preserve historical rationale and B's unadopted status. Reporting adoption of B fails. |
| 2. Quote changes but remains within budget | Preserve A's applicability under the stated budget condition. Blind reconfirmation/unknown or invalidation merely because a number changed fails. |
| 3. Late-imported older quote versus newer applicable quote | Use source event applicability rather than ingestion order; preserve the newer applicable state and older history. Blind unknown despite explicit ordering or overwriting the newer quote fails. |
| 4. Wrong entity within authorized scope | Keep the update attached to its own subject; preserve A's applicable premise. Similar wording must not create identity or justify reconfirming A. |
| 5. Unauthorized-scope near duplicate | Never read or send the unauthorized evidence; answer only from authorized evidence. Cross-scope discovery, linking or consumption fails even if the answer happens to match. |
| 6. Explicit, sourced adoption of B | Recognize B's recorded adoption in its stated scope; always answering unknown or merely proposed fails. Adoption comes from the source, not an edge or automatic supersession authority. |

Observe extraction proposals, admitted refs/receipts/qualification, discovered
endpoints, proposed typed edges, guard/truncation results, fetched and sent
evidence and first answer separately. Preserve all six slots and failures in the
fixed denominator, including failed extraction, qualification, discovery or edge
creation; do not condition reporting on correct upstream outputs. Normal capture
may omit or misinterpret a premise or edge: that locates the next intervention,
without justifying a seeded edge, case tuning or rerun to manufacture opportunity.
An API `reconfirmation-suggested` status alone does not prove a semantically
invalid premise. If no baseline error/opportunity exists, record STOP/re-scope.
A future isolated test may compare one mechanism only after this opportunity
check; no scenario sources, gold artifacts or whole cohort are authored or
executed here.

This is **not a frozen executable experiment**. Exact reviewed artifact SHA,
capture/answer/judge model versions, paired baseline, source/expected-answer
manifest, relationship vocabulary/direction, traversal and token/call/time/storage
ceilings, rubric, adjudication/firstness rules and affordability remain to be
fixed before any real model run. Offline wiring is the next engineering packet,
not completed work in this documentation packet. No observation or improvement
is claimed for these planned slots.

## Gates, ownership and verification

The single three-stage sequence is unchanged: Stage 1 diagnoses losses/unknowns;
Stage 2 uses 24 paired development cases and requires net correct gain ≥3/24,
improved targeted-stage evidence, no increased unsupported/stale use and no newly
failing severe case. Unknown safety blocks advancement. Stage 3 needs a fresh
30-case paired pilot with completion ≥29/30 and Cairn correct count ≥ same-batch
Mem0, fixed denominators and paired uncertainty. Independent reliability,
real installed Hermes new-session use and full write/update/read lifecycle
resource gates remain separate. Two unsuccessful controlled rounds require
hypothesis/ownership re-scope. Closed cases stay closed; no old-case tuning.
