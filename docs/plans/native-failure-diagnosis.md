### Ranked falsifiable hypotheses after the red loop

These concern public failure propagation and missing diagnostic classification,
not the actual upstream cause. Rankings were shared before targeted source
inspection; the observations below distinguish direct execution evidence from
source evidence.

1. Mixed `send` loses its transient termination distinction before retaining an
   attempt. Prediction: transport-throw and response-validation errors have
   different branches/codes but identical retained terminal attempt fields;
   adding only safe classification at this boundary would separate the red
   signatures without changing reservation or continuation. Observed: both
   terminal attempts are identical in the loop. Source: mixed `send` declares
   `termination`, sets `transport_failure` for the thrown transport, and raises
   `invalid_response` for response inspection failure, but `settle` stores
   outcome/cost/token/accounting fields without termination.
2. Native UDS forwarding erases the guarded error's specific code. Prediction:
   both guarded global errors are converted to `native_gateway_failed` while
   a sealed deadline or singleton 503 stays local. Observed: the loop's two
   globals share stage/execution while both controls preserve scope reason.
   Source: the server catch calls `firstFault(native_gateway_failed)` for an
   active or halted guard, except its explicit native-scope special case;
   `firstFault` preserves only its first code and halts the handle. No private
   gateway-error observer was inserted, so the exact internal code path is
   supported by source rather than newly recorded internal events.
3. Enclosing scope/runner catches further collapse specific global causes.
   Prediction: even a distinguishable gateway error will still give the same
   outer `scope_execution_failed` unless a separate safe observation survives
   the catches. Observed: both injected globals produce that exact report.
   Source: `withCaseScope` closes/revokes then throws `paid_work_halted` when
   globally halted; the runner's inner catch keeps only allowed local codes
   and stage/execution, and its outer catch assigns `scope_execution_failed`.
4. Continuation depends on authenticated local evidence, not unknown accounting
   plus pending 0 alone. Prediction: a real X deadline with terminal unknown and
   pending 0 proceeds locally; the same terminal accounting with unauthenticated
   transport failure halts; definite singleton 503 is separately permitted.
   Observed: all four injected paths satisfy pending 0/full reservation, yet
   their continuation differs as predicted. Source: `authenticateLocalUnknown`
   requires guard-returned failed deadline/cancelled scope identity, terminal
   ledger/transport and a non-halted guard; `unknownCurrentAttempt` separately
   exempts failed Mem0 embedding attempts. These safety distinctions are not
   disproved by the repro and should not be relaxed to repair observability.

### Safe classification seams for the primary's next decision

`constructMixedSourcePairGuard.send` is the closest source of truth for
transport entry, guard-owned deadline, bounded-body failure, invalid Mem0
envelope/usage and definite HTTP failure. A diagnostic-only enum could retain
these distinctions when settling the corresponding attempt, without raw error
strings, bodies, headers, hostnames, auth or caller hooks. Its classification
must be independent of outcome, cost, halt and local-authentication decisions.
`settlementFailure` already uses an allowlist of accounting operation/category
and preserves a priced observation when durable settlement fails; that seam
can distinguish accounting uncertainty from upstream transport. Global
pre-reservation verification/cap failures and native containment/reap/cleanup
faults are separate boundaries and must not be labelled upstream failures.

The existing `createTransportDiagnosticsCollector` is a useful design reference:
bounded 256 observations, closed-scope fencing and enumerated terminations. It
is wired into the non-mixed guard and allows only count/generation/answer/judge,
not native embedding/chat; the current mixed constructor has no observer
option. Direct reuse is therefore not currently an available mixed hook.
Native `firstFault`, scope close and the mixed report's per-ordinal attempt
summary are additional places to propagate a bounded safe category. A primary
repair must decide the schema, bound, ownership and privacy threat-model/test
updates before adding captured fields. No seam was changed in this dispatch.
