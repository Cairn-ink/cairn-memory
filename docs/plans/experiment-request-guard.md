## Acceptance T01–T08

- T01: An explicit constructor receives an existing experiment ledger config,
  immutable explicit request policy, and required injected fetch (no default
  network/key discovery). Reopen only, never create/reset budget. Expose separate
  host and Cairn fetch functions sharing this ledger. Pin exact model IDs and
  fixed per-channel positive reservation amounts, input/output/body bounds and
  rational integer prices supplied by the experiment operator, not guessed
  current prices. Policy is snapshotted before callbacks. Record its binding to
  the experiment durably or reject a changed policy on reopen; do not allow
  independent adapters to silently reinterpret the same budget.
- T02: Before reserve/send validate exact HTTPS OpenAI endpoint, POST,
  redirect:error, AbortSignal, string JSON body, bounded UTF-8 bytes, allowed
  model and closed supported payload shape. Cairn accepts only existing
  responses/input_tokens and responses payloads generated by the actual adapter,
  checking schemas and limits. Host accepts a deliberately documented nonstreaming
  text/function-tool Chat Completions subset with bounded messages/tools,
  max_completion_tokens, n=1 (or absent), store:false and stream:false. Reject
  remote/media/tool-execution modalities, unknown options and redirects before
  network. Do not mutate caller payload or replace existing provider defaults.
- T03: Every accepted HTTP attempt reserves on the existing ledger synchronously
  before injected transport; all three channels consume the shared request cap
  and ceiling. No refunds, implicit retries or fallback transport. External
  retries are new reservations. Exhaustion/lock/config/validation failure sends
  nothing. Test actual adapter count+generation plus host share the same ceiling.
- T04: Bound response bytes and elapsed time across both fetch and body read,
  propagate abort to transport, cancel readers and handle late rejection safely.
  Map failures to fixed content-free codes. Never retain keys, prompts, headers,
  bodies or arbitrary provider errors in ledger/policy metadata. Unknown usage
  remains null. Valid usage is accounted using integer arithmetic; over-reservation
  actual cost persists overrun and blocks subsequent requests. Invalid/partial
  responses cannot yield invented zero-cost success. Return buffered response
  only after successful accounting. Document transport success versus semantic
  validity and that observed priced usage is an estimate, not invoice proof.
- T05: Verify separate handles/reopen, exact shared limits, mutation races,
  rejected models/options, failures before/after transport, missing/malformed
  usage, overrun, response-size overflow, cancellation, hung fetch/read and retry.
  Use synthetic private ledgers and fake HTTP only on Node22.16/24; no real keys.
- T06: Exercise a real public core operation with the actual OpenAI adapter
  behind guarded fake HTTP and a host completion using the same ledger; primary
  independently repeats an integrated positive path and failure/no-send path.
  No second memory engine or modifications to deployed/private/Hermes profiles.
- T07: Add runnable synthetic demo, API/limitations guide, contributor test gate,
  CI and changelog. No implicit live CLI. Full pinned Hermes transport routing,
  audited model prices/upper bounds and new paid approval remain explicit gates;
  passing this slice must not declare V05 or real-chat success complete.
- T08: Primary verification then final fixed-base independent Standards and Spec
  reviews, corrections and rereview before push/PR. No self-merge/release/deploy.
