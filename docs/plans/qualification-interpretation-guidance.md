# V2 qualification interpretation guidance (S6d)

Fixed base: `7766ffe36d02d7d2833ea74cc29b33441e898464`.
Private dependent worktree: `qualification-interpretation-guidance`.
No paid calls, public delivery, publication or deployment in this slice.

The frozen S5c six-case pilot had mostly unknown descriptive fields and one
assistant proposal labeled direct. This is separate from source-offset and
canonicalization mechanics. Improve interpretation instructions without making
unsupported completeness a runtime requirement or rescoring that experiment.

## Acceptance

- Q1: Change only the v2 qualification prompt, explanatory documents and scoped
  tests. Compiler, storage, schemas, enums, v1/legacy prompt bytes, request
  methods, budgets, candidate rules and authority boundaries remain unchanged.
- Q2: Evaluate fields independently. Preserve useful supported descriptors even
  when commitment is unknown; null/unknown remain valid when unsupported. Do not
  infer identity or copy example facts; impose no runtime non-null quota.
- Q3: Explain attribution of the underlying remembered assertion: proposed for
  offered/hypothetical action, quoted/reported for attributed words/claims, direct
  for the source's own assertion/experience/preference, unknown for ambiguity.
  Firsthand observation of a suggestion does not make its content direct or
  adopted. Role, confidence and kind do not establish adoption. Do not invent
  enum precedence for ambiguous nested speech.
- Q4: Distinguish settled choices, considered options, explicit rejection and
  unknown commitment. Not adopted is not rejected; a question or suggestion is
  not user adoption. Preserve temporary conditions and uncertain feelings; do
  not invent permanent traits or reasons.
- Q5: Provide one source-bound coffee/sugar JSON example (excluded from future
  fresh cases). Independent offline tests parse it and exercise the real v2
  compiler, exact anchors and continued all-unknown acceptance. Test actual
  adapter prompt framing with unchanged method/schema/source limits/budgets.
  These are contract tests, not semantic evaluation of a model.
- Q6: Root verifies both Node 22.16 and 24 generic, JSON, plugin, core, OpenAI,
  MCP, artifact and live-offline gates plus store/capture/OpenAI-offline demos.
  Installed artifact prompt bytes must match. Freeze a local candidate and run
  independent Standards and Spec review on that exact head. Previous results
  remain unchanged; semantic improvement requires a separately frozen fresh run.

## Limits

The existing attribution enum mixes speech relationships and does not resolve
every nested utterance. This is guidance, not a domain/schema change, a semantic
guarantee, automatic identity matching or a rationale dependency implementation.
Public delivery remains held for security coordination.
