# Offline synthetic evidence lineage

Base: `aaa44da256cfdcd9218efe1e2d53e19229dbb943`. Scope: an evaluation-only, fixed synthetic fixture suite. This diagnoses where a deliberately scripted source stops moving through the existing pipeline. It is neither a semantic benchmark nor a change to product capture, recall, scoring, or telemetry.

## Contract

1. Run fixed, short synthetic histories through `runPublicComparison` backed by a fresh `openMemoryCore` store per scenario. Its ordinary capture, recall, provenance check, and answer packing must execute. The model and answer callbacks are scripted; no provider, configuration, environment input, corpus, or saved user data is read.
2. Observe each source at these boundaries: extraction proposal, admitted receipt, filing status, visible selection map, selected reference, rank input and output, final returned memory, and Cairn answer-packed receipt. Link using transient message, memory, and receipt identities; emit only fixture-local ordinal handles and closed statuses. A linked receipt proves plumbing, not that a needed fact survived interpretation or is true.
3. Fixed cases demonstrate extraction omission, extractor failure with unavailable evidence, classification failure after admission, visible but unselected, selected but rejected by rank, delivered receipt, and final answer-packing omission. An unobserved boundary is `unknown`, never counted as loss or zero. In particular, classification failure prevents comparison recall, so downstream observations are unknown.
4. Observer callbacks snapshot only the bounded relation needed before forwarding or after return. They never alter request, result, order, or error. No oracle labels or expected answers enter model input. Expectations are assertions after execution. The report has fixed shape, bounded rows, explicit overflow/unknown state, and no source text, question text, raw IDs, paths, exception strings, or hashes derived from source data.
5. Tests exercise the real pipeline from capture onward, including the negative cases, repeated independent calls, report redaction, unknown stages, and answer packing. The CLI prints concise numeric/status output with `synthetic: true` and `semanticAccuracy: 'not-measured'`. Run scoped tests and demo on Node 22.16 and 24.15, then repository generic checks.

## Threat boundary and limits

This is a local maintainer diagnostic. The source, prompts, receipts, and database exist transiently in private temporary files and callbacks while a case runs; the returned report has only ordinals, counts and status enums. Each fixed case has at most four source turns and five admitted memories. More than eight calls at any observed stage sets `overflow` and makes all per-source fields unknown. It neither adds a public observer interface nor sends captured metadata to hosted telemetry. The synthetic scripts intentionally cause each failure and are not a held-out model evaluation. Historical runs lack this lineage; no eight-question diagnosis, accuracy score, or product reliability claim follows.

The scripted selector and ranker order returned references by labels and receipt excerpts already in their own model inputs. These are fixture controls, not evidence of relevance. `selected` and `rankOutput` are model-returned refs before core validation; `returned` is the actual core response; `packed` is the first Cairn answer request after the public comparison's own packer. The answer callback never judges correctness.

## Verification record

Implementation owner: bounded worker on `test/synthetic-evidence-lineage`, fixed base above. Both Node 22.16 and 24.15 passed the scoped architecture tests (2 tests), `npm test` (112 tests), and `npm run demo:synthetic-lineage` (seven fixed scenarios). `npm run validate` passed. The demo observed two ranked and returned receipts with exactly one omitted by answer packing; the classification-failure and extractor-failure cases left downstream stages unknown. Separate primary-agent direct-admit control: with 1,025 current unfiled rows, a unique query for the maximum-ID row yielded neither visible nor returned target; after forgetting one different low-ID row, with 1,024 current rows, the same target was visible and returned. This is a candidate-discovery capacity control, not part of the capture-based lineage suite or an accuracy statistic. A future retrieval change needs a positive beyond-prefix regression.
