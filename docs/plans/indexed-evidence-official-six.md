# Indexed evidence: fresh official six-type feasibility pilot

Prospective contract, 2026-09-28. This follows the four authored synthetic cases
in PR #274; it does not replace, replay or pool those results. The goal remains
a lightweight, reliable memory layer usable by external harnesses. This packet
tests whether the existing opt-in evidence route completes official long
histories and yields scoreable answers, not whether it achieves 100% accuracy.

## Fixed scope and acceptance

- S1 — Freeze one previously unused question from each of the six official
  LongMemEval types using ID/type metadata only, a prospective seed and the
  audited 142-ID exclusion union, including unexecuted reserved cohorts.
  Freeze all 148 future exclusions before inspecting selected history length,
  cost or answers. Preserve corpus order and alternate the first arm 3/3.
  Never replace an expensive, unready or failed selection.
- S2 — Use public runtime `19623ad277c3552e041d4c793313fda178b98b61`,
  explicit `indexed-evidence-v1`, native Mem0 2.2.0 and the previous pinned
  models, prompts, source revision, chunking and native settings. Product
  default MOC navigation is not this experimental route. Do not silently
  substitute the older qualified profile or its resource projections.
- S3 — Prepare separated source-only histories/questions and deferred reference
  data. Authenticate the complete runtime, native dependencies and each input.
  Generation cannot read the evaluator. Only after durable generation may
  scoring read verified references and use the pinned Python official-style
  renderer for nonstring answers. Never expose corpus, keys or capability data
  in public artifacts.
- S4 — Project the actual whole batch vector and each singleton with the current
  indexed-evidence resource planner. Keep the existing cumulative US$200 ledger
  and request cap, a US$10 protected remainder and this pilot's prospective
  US$30 reservation ceiling. Require a fresh authenticated, settled checkpoint
  and all finite phase/per-arm bounds before any paid call. No refund, reset,
  reroster, replay, retry or new budget lineage. Unaffordability is a retained
  preparation failure, not permission to weaken a bound.
- S5 — Adapt the already reviewed private preparation/operator, using owned
  synthetic workspaces. Test source/reference separation, deterministic fresh
  selection, indexed profile propagation, bounds, deferred rendering, durable
  evidence, incorrect pins/checkpoints, one-shot refusal and failure handling
  on Node 22.16 and 24.15. Independently review both Standards and Spec on exact
  helper hashes before preparation and again before paid execution. Primary
  reruns key tests and the actual-core/native-Mem0 fake-HTTP gate.
- S6 — Execute the frozen cohort once only if all gates pass. Preserve all twelve
  scheduled arm outcomes. A settled authenticated per-case deadline remains
  failure and may continue to the next fixed arm under the existing policy;
  accounting, global or unsettled failures stop the cohort. Do not salvage
  partial answers into completed runs or repair results after looking at them.
- S7 — Report ingestion completion, nonempty answers, common resolved judgments,
  correct/incorrect/unresolved counts, actual calls, conservative reservations
  and known usage separately. Feasibility passes only when both arms complete
  all six ingestions/answers and all six paired judgments resolve. Correctness
  is a separate measurement, not a 100% gate. Report any failure as observed.
- S8 — Publish reproducible protocol and aggregate evidence with limitations;
  update `docs/limitations.md` and `ROADMAP.md`. A six-case cohort is not a
  full 500-question score, credible overall competitor ranking, causal ablation,
  proof of ordinary MOC reliability or MCP/Hermes end-to-end readiness. Consider
  a separately frozen larger comparison only after this gate and a new resource
  check; do not assume the remaining budget can afford it.
