# Retained-window source-availability control

Status: approved for the synthetic-only offline implementation described here; no paid run, default change, or product retention decision is authorized. Fixed starting point: `0fe007f26e89a968bec1f9a741431bbe206dfc7d`. The accepted five-case aggregate contains 220–234 completed cards per case and no receipt from the annotated answer-bearing turn in two cases; it does not establish that equivalent support was absent, why a turn was omitted, or that retaining it would produce a correct answer. This control tests a narrower structural question: if canonical source windows are durably offered to the *existing* core, where can their source evidence be reached after a cold reopen?

## Comparison and non-claims

Use two fresh, separate, synthetic SQLite databases with identical namespaces, input batches, questions, local token counter, and source-evidence recall configuration. The baseline calls real `core.capture` with `captureSourcePolicy: 'indexed-evidence-v1'` and `sourceCandidatePolicy: 'bounded-keyset-v1'`. Its fixed, query-blind scripted extractor proposes the first five of each six-window batch as `kind: 'context'` with exact indexed source receipts; its scripted classifier leaves admitted memories unfiled. The sixth canonical window is deliberately *not proposed*. The diagnostic control calls real `core.admit` once for **every** canonical window, with `{memory:{content: window.content, kind:'context'}, receipts:[{client,sessionId,eventId: message.id,role,excerpt: window.content}]}`. It does not call `capture`, and its admission has no extraction, classification, capture replay, or capture-deadline semantics. Direct admission is trusted synthetic fixture setup, **not** evidence of automatic capture or permission to retain production conversation text.

Both arms use the same `openMemoryCore`, `core.get/list`, `core.recall({contextMode:'source-evidence', selectionMode:'bounded-source-scan'})`, `correct`, and `forget` interfaces; no sidecar engine, raw-text archive, storage-schema change, new admission API, default change, or MOC/vector tuning. The comparison cannot by itself establish semantic answer quality or a product privacy policy. It may show that retention is necessary but insufficient because recall or packing can still miss a durable receipt.

API anchors at this base: [`captureSnapshot`](../../core/capture-input.mjs) enforces ≤24 messages, ≤4,000 units/message and ≤20,000 units/batch; [`sourceWindowCatalog`](../../core/source-windows.mjs) emits exact ≤800-unit windows and ≤64 entries; [`extractedWindowItems`](../../core/source-windows.mjs) uses the submitted indexed sources. [`openMemoryCore`/`admit`/`get`/`correct`/`forget`/`recall`](../../core/contract.mjs) supply the real storage and read lifecycle. [`recallMemories`](../../core/recall.mjs) limits selection to two rounds and ranks fetched source DTOs once; the bounded-keyset path scores current bodies and up to four stable-ID receipts per row ([candidate implementation](../../core/moc-storage.mjs), [contract](../source-evidence-context.md)). These bounds, rather than any new retention mechanism, constrain the control.

## Observation contract

Record fixture-local ordinal handles, counts, stage status, and bounded diagnostics; do not persist source text, answer keys, target IDs, or internal memory IDs in a public report. Keep transient ID-to-receipt joins in the test process. Each source/question pair has distinct observations:

1. **Offered/proposed:** canonical window exists in the submitted snapshot; for baseline, whether extractor proposed its index; for control, whether a direct `admit` call was made. The control's “offered” is not an extraction proposal.
2. **Durable/current:** after closing and reopening the real core, paginate exact-namespace `list` and each `get` receipt cursor to exhaustion, then bind the canonical excerpt plus `client`, `sessionId`, `eventId`, and `role` to a current memory revision. Inspect all receipts, not only the first carrier. A deduplicated memory can carry multiple source receipts; a content match alone does not prove source identity.
3. **Candidate-visible:** the relevant current memory/ref appears in a real source-evidence map/candidate packet. Record only exposed map item/ref, `exhausted`/cursor signals in the actual public page or callback input, returned recall `coverage`, candidate count, and whether its receipt text is visible. The map epoch is held privately by core freshness checks and is **not** a model-request field; report epoch as unavailable unless an existing public result actually exposes it. A page that omits a source while `coverage: 'budget_exhausted'` or cursor work remains is **not** proof that the source is absent from the index.
4. **Selected/ranked/final:** record whether the source-bound ref was accepted by the actual select callback, presented to rank, accepted by rank, and returned by `core.recall` with its current revision and exact receipt. Labels are routing previews, not source evidence. Keep “not observed,” “bypassed,” “budget exhausted,” and “observed no” distinct.
5. **Packed:** give `packMixedAnswer` only the exact returned receipt excerpts, at most six units, then observe whether the source text is present in the resulting bounded request and whether packing omitted it. No answer generation or scoring. Source presence in a pack is a plumbing observation, not a correct answer.

The select and rank callbacks may read only their actual `request.system/input`. Their exact rule is frozen now: use `createQueryScore(request.input.query)`; for each visible map item, score only its `label`, discard score zero, sort descending by score with original page order as the tie-breaker, and return the first at most 12 refs per namespace and 24 total through the existing `unfiled`/memory-ref conversion. For rank, score each candidate by the maximum over its exposed receipt excerpts, discard score zero, sort descending with original candidate order as tie-breaker, and return at most `min(request.input.limit, 6)` current refs. No callback may use fixture metadata, target IDs, gold answers, database rows, or an oracle routing table. The local exact-token counter is used for core budget enforcement and pack measurement. Do not require every stage to pass merely because the control retained a source: durable-but-not-candidate, candidate-but-not-selected, rank omission, final omission, and pack omission are legitimate discriminating outcomes. Conversely, a successful structural trace does not prove semantic improvement.

Reuse `createIndexedSourceWindowObserver` for each baseline capture: it accepts up to 64 offered windows and **up to five capture members**, checks the completed admission against current member revisions, and reads all receipts for each member up to its 100-receipt bound. Its scope is capture-members-only/current-read; it cannot observe direct admission unmodified or prove recall selection. `createRetainedRecallTrace` is **one exact source carrier/probe, one actual recall and pack**; instantiate it separately per source probe when its complete `get` and one-namespace preconditions hold. Never splice stages from different cards, carriers, or recall invocations into one success trace. Existing `locateMixedSourceFamily` is tied to the mixed runner's `cairnPlan.batches`, completed capture outcomes, and ≤5 admitted members, so it is not a drop-in for the direct-admit arm; reuse only if those inputs genuinely fit. If multi-carrier composition is needed otherwise, use a separately approved evaluation-only family observer preserving exact carrier identities, or mark family status unavailable. Existing `createQueryScore` is exact lexical scoring, so paraphrase failure is evidence about reachability, not proof of missing retention.

## Lifecycle and isolation controls

After the frozen initial-card/read phase, use separate fresh synthetic lifecycle fixtures through the same real core. Cold-close/reopen between writes and observations. Correct an existing source-backed context memory with `core.correct({namespace,memoryId,expectedRevision,content,kind,receipt})`: the old receipt/text must not be returned as current evidence, the replacement receipt must bind the new revision, and an old-fingerprint re-admit should be suppressed according to actual core behavior. Forget another memory with `core.forget({namespace,memoryId,expectedRevision})`: old content/receipts must not return, and suppressed content must not silently reappear. Admit the same exact text under two event receipts to measure dedup and *both* source bindings, then use an exact same-text admission in another namespace to prove no cross-namespace visibility. These are explicit-lifecycle/direct-admission controls, not claims that automatic capture detects contradictions or forgets an inferred decision link. Record any API nonfit instead of inventing correction/replay behavior.

## First complete 32M offline trial

The first full pinned Node 22.16 run completed in 33,670 ms, with 27,631 ms of collection time, zero provider calls, exact cold five-field source tuple sets of 250 baseline/300 control, and 50 baseline extract plus 50 applied-classification calls. The existing baseline capture observer found five retained of six offered windows in each batch; the control direct-admitted all six. Baseline/control SQLite file sizes were 1,077,248/1,093,632 bytes after collection and at the final read; WAL/SHM were zero in this run. Shared local count-work was 17,331,529/32,000,000 tokens; callback input/output totaled 230,385/2,000,000 tokens. Per-arm local count-work was 13,978,633 baseline and 3,346,747 control; lifecycle used 3,300, and report measurement 2,849. These are local tokenizer work and scripted callback measurements, not provider usage or an SLA.

Q1's omitted primary source was not retained in baseline; the direct-admit control delivered that exact current source through final read and packing. Q2's retained primary source reached packing in both arms. Q3's paraphrase probe reached the control's source, but this does not assess answer semantics. Q4 exposed **both** the primary and the obsolete decoy in the control pack; baseline exposed only the decoy. This is a source-availability comparison, not conflict resolution. Q5 had no named source in the fixture, yet both arms returned six other sources; that is not an answer pass. All Q1–Q5 recalls reported `budget_exhausted` coverage, so none proves exhaustive absence outside its observed packet. A separate direct-admission lifecycle DB showed cold corrected-source Q6 delivery with `complete` coverage and real-core correction, forgetting/suppression, duplicate-carrier and namespace-isolation controls. No answer model ran. Source trace status and `delivered: false` mean only “not verified delivered” where applicable, not proof of source absence. The fixed fixture remains SHA-256 `9354e0c21e1d01827129945125ae167e5aec6178076c60f0b573cab0c7be84db`.
