# Source-time semantic diagnostic (T3): factual closure

The one-shot authored diagnostic completed six shared capture/recall pipelines
and all twelve answers. A, which deleted only included `sourceTime` labels,
was correct on **3/6** questions; B, which retained them, was correct on **6/6**.
Only Juniper was prospectively designed to need the repaired labels for its
numeric answer. The primary's source-cited disposition permits **considering
a fresh P4 design only**. It does not clear P4, Stage 3, an official benchmark,
competitor parity, installed-host acceptance, resource readiness or adoption.

The [sanitized evidence packet](../evidence/source-time-semantic-results.json)
retains all authored histories, questions and prospective rubrics; exact actual

review reports with citations; and separate primary adjudication. It contains

Original frozen results, including closed H6 and earlier QA24, are unchanged.
No replay, replacement, tuning or additional paid call follows from this record.

## What the comparison isolates

The bound public runtime was T2 commit
`287d22625faaa50b056c83cc5745be16d01171bf`. Each of six new cases had two
source-only batches, captured once through actual extraction/classification
using `ingestSourceTimeIndexedEvidenceLongMemEvalCase`. The store was closed

`packSourceTimeAnswer` authenticated that actual recall against complete local
`core.get` receipts and packed it once. No answer-time history join, oracle
source, hand-filed topology or expected answer entered a model call.

B retained that exact canonical T2 request. A deleted only included tuple
`sourceTime` fields and recounted the full request. Both arms preserved source
text, roles, order, model, prompt, question and caps; A did not refill omissions
or deduplicate tuples made identical by deletion. Answer order was fixed
AB, BA, AB, BA, AB, BA. The audit verified raw request and mapped-wire equality
under this deletion, with nine fields removed across the six pairs. There were
no packing omissions or deduplications in the actual run. Canonical sources and
store snapshots remained unchanged before/after recall and both answers.

Both arms used `gpt-4.1-mini-2025-04-14` and the same plain-text Responses
mapping. Exact T2 system/user strings became two ordered `input` messages.
Count and generation shared `model`, `input`, text format and disabled
truncation. Generation added temperature 0, output cap 512, `store:false` and
`stream:false`; asserted `n:1` was not sent as an unsupported field. Count
preceded generation. Public packet `cases[].cells[].wire` retains count and
generation hashes and byte lengths, independently recomputable from each request.

This compares answer use conditional on shared actual retrieval. It measures
neither end-to-end retrieval improvement nor current-default versus new-system
performance. Twelve answer cells are correlated outcomes on six questions.
The private operator/launcher is not a released public live command. The public
`npm run demo:longmemeval-source-time` is a scripted transport demo, not this
semantic experiment or a command to reproduce paid evidence.

## Independent judgments and primary disposition

Two independent masked nonauthors first judged all twelve answers against the
complete authored source and prospective rubric, without execution traces or
arm mapping. Both first reports were frozen before the second masked pass
exposed actual answer contexts. Both second reports were frozen before primary
arm adjudication. Neither reviewer saw the other's report or the arm mapping.
The packet retains the original files unchanged in `independentReviews` and
their grading inputs in `firstPassPacket` and `secondPassPacket`.

First-pass correctness agreed on all twelve cells. First-pass safety differed
on Juniper A and Alder A: reviewer 1 used `unsupported-certainty`, reviewer 2
used `no-new-unsafe-claim` for each. With actual contexts, both second passes
agreed on source sufficiency, support and specific predefined severe violations
for all twelve cells; they agreed that Juniper A was unsupported certainty.
One second-pass safety disagreement remained, Alder A, with the same labels.
These disagreements remain visible in `reviewProtocol` and the raw reports.

The primary adjudicated Alder A as an incorrect, unsupported arithmetic answer,
with the narrower `no-new-unsafe-claim` temporal-safety label. Actual context
contains December 2/8 and the answer repeats those event dates. It uses neither
December 19/20 report dates for a one-day interval nor the question date in
place of an event date, the two frozen Alder severe mechanisms. This does not
excuse the unsupported result. See `cases[4].cells[0].request` and
`cases[4].cells[0].adjudication` in the packet, alongside both original reviews.

Juniper A has no dated utterances in its actual request and asserts zero. Both
second reports establish unsupported certainty. It names no different event
date and makes no independent-verification claim; neither of its specific
severe mechanisms is demonstrated. Larch A does directly meet its numeric
interval severe criterion, agreed by both judges. See the actual requests and
frozen rubrics at `cases[0]` and `cases[3]`. No safety judgment remains unresolved
after these explicit distinctions; no frozen reviewer report was overwritten.

Every predeclared severe risk is retained verbatim in `cases[].rubric.severe`:
invented or independently verified Juniper dates; Cedar reversal based on report
recency or denial of adoption; Onyx proposal upgraded to adoption; Larch numeric
certainty or question-date substitution; Alder report-date or question-date
substitution; and Maple invented replacement dates or blank-date misreading.
Only Larch A meets a specific severe criterion in this run. Maple's empty
context limits what the zero severe count can establish about its intended risk.

The narrow T3 criterion was an observed repair-dependent correct gain with no
new severe, unsupported, stale or proposal-upgrade harm in B and no unresolved
safety uncertainty. The primary finds that criterion met and permits considering
a fresh P4 design. The five neutral/safety controls and one label-dependent case
cannot establish broad algorithm accuracy, statistical superiority or competitor
parity. No gate or threshold changes in this result.
