# Next hypothesis after selective-correction evidence

## What the observed run does and does not show

The fixed three-case diagnostic reached all supplied sources and persisted every
accepted proposal. In the mixed case, an older encryption observation (arriving
last) was used to challenge a later explicit loss. The genuine loss challenge
and its separate historical support disappeared from the replacement graph.
The decision view consequently became `unassessed`. The source text in its
self-support still mentions both original reasons; not all reason text vanished.

This is a semantic direction/coverage failure, not a missing-source retrieval
failure. It does not prove that arrival order caused the mistake. The current
relation prompt defines scope and attribution but does not explicitly separate
event time from import time. Replacement also treats omission as withdrawal;
that is its documented contract, not proof that omitted links became invalid.
No quality promotion follows, and this once-only diagnostic must not be rerun.

## External reference, not a product guarantee

Zep describes a separate dating step and comparison with existing edges during
graph creation, rather than treating each inference as a complete replacement:
[graph creation](https://help.getzep.com/how-graph-creation-works), checked
2026-09-17. Its [fact timestamps](https://help.getzep.com/facts) distinguish
when information was learned from when the fact held. These are useful design
patterns, not evidence that extraction or invalidation is always correct.
