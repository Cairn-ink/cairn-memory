# Proposed 14-day local-memory adoption experiment

Status: prepared, not launched. Start the clock only after an owner-approved
release and a passed source-support gate; no publication or outreach is
authorized by this document. A ten-person private alpha is not a prerequisite.

## Hypothesis

Developers seeking an inspectable, lightweight MCP memory layer will complete a
first write and later-session sourced recall without a Cairn hosted account.
The reason to try Cairn is the working local memory loop and inspect/correct/
forget controls, not a promised star count or unsupported accuracy comparison.

## Observation window and success signals

Observe 14 days from approved release. Offer the same install instructions and
synthetic walkthrough to every participant. Record denominators as well as
successes; an unfinished install or missing recall remains a failed attempt.

- Activation: first successful write, then useful recall of that memory in a
  different process/session, with a valid Source Receipt the user can inspect.
- Directional first-ten checkpoint: 10 attempts, 6 activations and 4 participants
  reporting a useful sourced recall. These are proposed learning targets, not
  measured outcomes or a guarantee.
- Collect installation friction, unsupported/invented details, unwanted recall,
  redaction misses and whether the participant would use it again. Safety defects
  take priority over acquisition work.
- Observe GitHub stars and voluntarily reported discovery channels as secondary
  aggregate signals. Do not set a star count as an engineering acceptance gate,
  buy/incentivize stars or claim stars equal users.

## Channels and consent

An [engineer-focused introduction draft](../local-memory-introduction.md) is
prepared, not posted. Prepare, but do not send, one
Hermes-specific installation note once native integration is actually verified.
Owner approval is required for recipient/channel scope and public posting.
Do not claim upstream listing or endorsement from third-party installation.

Use voluntary content-free feedback: attempted/completed steps, host/runtime,
error code and usefulness rating. Do not request raw conversations, memory
contents, API keys or database uploads. Do not add hidden telemetry to core.
An aggregate GitHub metric is not an identity-linked activation event.

## Decision after 14 days

Publish no invented conclusion if participation is low. Compare observed
attempts and activations; fix the largest reproducible onboarding failure first.
If source support or deletion/isolation fails, stop expansion and diagnose it.
Human feedback complements—not replaces—the frozen engineering evaluation.
