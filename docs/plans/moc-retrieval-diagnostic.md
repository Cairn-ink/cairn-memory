## Sequence

1. Isolate retrieval from extraction/reconciliation: explicit correct synthetic
   memories, manual organization, cold SQLite reads and stage observations.
2. Independently fix the proven classification-catalog bottleneck; more memory
   bodies must not imply the topic catalog is incomplete. Keep completeness and
   authority checks. Separate PR, no MOSS/private-engine changes.
3. Use diagnostic evidence to select query-aware candidate generation or actual
   hierarchy routing. Compare an honest flat lexical baseline, including Chinese
   limitations; do not assume the hierarchy wins.
4. Verify offline, independently review, then evaluate separately frozen new
   queries using real models within the phase grant. Keep correct-answer and
   correct-evidence metrics separate. Update failures remain a separate open gate.

## Acceptance for this diagnostic (D1–D7)

- D1: actual public core and fresh synthetic SQLite only; no provider key, network
  fallback, changes to product runtime, old paid fixtures or user databases.
- D2: generate a fixed reproducible matrix at small and above-two-page sizes,
  correct versus deliberately misleading topic placement, unfiled distractors,
  exact English/CJK queries, and lexical mismatch/paraphrase controls. Retain
  generated IDs and target page positions; do not select favorable random runs.
- D3: record target existence/direct-read support, complete map inventory,
  visibility in actual bounded recall select inputs, selection, fetched/ranked
  evidence and core coverage separately. An explicitly labeled visibility oracle
  may choose known target IDs only when visible; it is an upper-bound diagnostic,
  never a semantic-quality model or an unbiased retrieval score.
- D4: compare corpus-wide SQLite FTS5 BM25 using unicode61 on the same active
  synthetic memory content, with query-derived escaped tokens only (no target
  IDs/answer labels in lexical ranking). Document Chinese segmentation and
  paraphrase limitations. Equal output limit, report differing candidate work;
  do not claim identical compute or token budgets.
- D5: measure corpus size, emitted map items/bytes, model callback counts, local
  elapsed times and lexical results; offline counting must be explicitly marked
  synthetic, not real tokenizer/provider cost. Repeated UUID ordering may vary;
  qualitative late-topic reachability results must not depend on that ordering.
- D6: include a separate small/large unfiled classification control that proposes
  the same first category, logging actual catalog completeness/proposal outcome.
  A failed case remains failed; model false/invalid responses are not repaired.
- D7: public source/rubric/evidence contain synthetic data only. Tests prove
  late-topic invisibility even to the oracle, full direct/inventory reachability,
  baseline no-oracle behavior, namespace isolation, cold persistence, bounded
  callbacks and retained failures. Both Node22.16/24 generic + relevant offline
  gates, independent Standards/Spec review before PR against main.

This harness is an architecture experiment, not a shipped search engine or a
competitor benchmark. Source-derived findings and literature-informed proposals
must be distinguished from measured real-user benefit.
