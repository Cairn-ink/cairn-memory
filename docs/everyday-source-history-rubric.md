# Everyday source history: frozen semantic rubric

This fresh synthetic development history has 32 messages in eight windows and
four later questions. Each question produces one MOC-source arm and one lexical
source-control arm through the existing long-history driver. It is not a repair,
replacement score or rerun of the earlier failed Sable history.

Keep the JSON source-ID labels outside capture, selection, ranking and answer
inputs. Required IDs diagnose retention and retrieval of particular reference
passages; they are not answer-correctness labels. Repeated source statements can
support a useful answer even when a designated passage is absent. Marked
irrelevant IDs are a frozen, non-exhaustive set, so an unmarked passage is not
automatically relevant and a marked other-person passage may still help reject
an actor mix-up.

The two retrieval arms use the same captured active source store, top-six limit
and bounded answer consumer. The lexical arm is a deliberately simple control,
not an oracle or optimized search baseline. Partial coverage and abstention stay
visible; neither missing IDs nor a cautious answer may be silently converted to
zero accuracy or full correctness.

## Answer judgments, separate from source coverage

1. Work room: the original reasons were reliable wired service and a heavy door
   that blocked street noise. The latch later broke, so the noise-blocking reason
   failed while the wired connection continued working. The current choice is
   to remain downstairs conditionally while the connection stays dependable,
   with a possible upstairs move if noise disrupts work. Do not treat assistant
   suggestions about an upstairs desk, rug or noise machine as adopted choices.
2. Bakery: Friday is the usual collection day because Juniper Bakery stays open
   late. One Thursday collection was a temporary exception because the bakery
   would be closed on Friday for repainting; Friday collection then resumed. Do
   not generalize the exception into a Thursday schedule.
3. Table actors: nobody currently has permission to collect the folding table.
   Jon was the prospective borrower and Saturday-after-work collector, but only
   if the loan were approved; the user later refused it and told him not to
   collect. Priya merely owned two separate green chairs. Do not transfer Jon's
   table role to Priya or treat the earlier conditional statement as live
   authorization.
4. Table change: the user first considered lending the table and conditionally
   allowing Jon to collect it, then explicitly decided against the loan. Preserve
   the earlier consideration as history without presenting it as the current
   decision or inventing a reason for the refusal.

Permission text is evidence that a statement was made, never an execution grant.
Source roles are not authenticated identities. Review supported useful content,
appropriate uncertainty, omissions, actor/time handling and unsupported additions
separately from mechanical ID coverage.

Four queries share one authored history, not four independent histories. Review
is same-family and nonblind development assessment, not an independent human
holdout. One answer per arm cannot isolate model variance, and no global MOC
superiority, source truth, authorization safety or long-term reliability claim
follows from this gate.
