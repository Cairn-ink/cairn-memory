# Source-linked answer accounting (offline experiment)

This candidate makes a host's interpretation inspectable in the same response
as its answer. It does not implement a new memory store, change MOC retrieval,
or certify that a source-supported-looking statement is actually correct.

The retained augmentation comparison exposed two separate problems: evidence
can disappear before the answer, and even complete evidence can be interpreted
incorrectly. More candidates did not reliably fix either. This experiment holds
retrieval constant and asks whether separating choice, commitment, scope,
original reasons, later evidence and unknown information helps the answer stage.
No semantic improvement has been measured for this candidate.

## Prepare, generate once, inspect

`prepareSourceAnswerAccounting` in
`evaluation/architecture/source-answer-accounting.mjs` accepts serialized JSON
with the existing synthetic answer shape `{question,sources}`. Sources retain
`{id,role,content}`. The caller must first verify their exact mapping to finalized
memory identities/revisions and complete receipts, or explicitly identify them
as a synthetic canonical control. The compiler cannot verify that mapping or
future database freshness itself. Do not pass summaries as original receipts.

It returns a frozen instruction, input object, fixed1024 output-token allowance
and a compiler. A separate already-authorized caller would make **one** model
generation and pass the raw JSON response to `compile`. This package includes
no transport, provider key, grant, retry, second drafting call or automatic
production integration. Its injected tokenizer must be a trusted local counter.

The response contains a concise `answer` alongside:

- `choice`, `commitment` and `scope`, each a cited interpretation or null.
- `reasons`, with each original reason, separately cited later evidence and a
  proposed current interpretation or null.
- `unknown`, requested information not established by the supplied evidence.

Every cited interpretation is `{text,sourceIds}`. Full enclosing source text
remains available; the representation does not slice away a surrounding negation
or another speaker. It reuses the decision/premise/update distinctions already
present in the shared engine's decision-basis work without adding a link graph
or persisting model-proposed relations as truth.

Null means unresolved, not disproved or universally applicable. Empty `later`
means no update represented, not proof that no update exists. A surviving reason
must not silently strengthen a tentative choice. A failed premise alone does
not establish a replacement decision. A future return remains a plan, and a
remembered choice or past consent is not an execution grant. If budget approval
is not recorded, neither approval nor its approver is established.

## What validation proves

The compiler checks exact closed JSON fields, bounded lengths, known distinct
source IDs per claim, valid Unicode and unchanged source contents. It preserves
all supplied sources, not just those cited, in a deeply frozen result marked
`interpretationStatus: model-proposed`, `semanticStatus: unassessed`,
`sourceSelectionCoverage: unassessed`, `executionAuthority: none`.

It intentionally cannot reject every semantically wrong interpretation. A
structurally valid statement that old cheapness still holds, that a tentative
choice is confirmed, or that an assistant granted permission remains an
**unassessed proposal**, never verified memory or usable authorization. The
prose answer can also disagree with its own record. Independent semantic review
must inspect both; citation counts and populated fields are not fidelity scores.

Input JSON is limited to24000 UTF-8 bytes,24 sources of at most800 UTF-16 units
each and a4000-unit question. The instruction plus serialized input must fit6000
local tokens. Output JSON is limited to16000 UTF-8 bytes and1024 local tokens;
the answer is at most4000 units. Records allow eight reasons, four later claims
per reason, four source IDs per claim and six unknown items. Individual claim
and unknown text is at most400 units. These simultaneous limits may reject a
complex response. There is no truncation, repair or budget enlargement.

Local token limits do not measure provider framing or prove an invoice bound.
A future transport still needs its own existing request/output/context limits,
budget checks, cancellation and bounded decoding. JSON strings at the compiler
boundary avoid invoking caller-owned object getters or serialization hooks;
they do not make untrusted source text an instruction. Detected secrets are
rejected, not silently redacted into different evidence. Redaction detection is
not a guarantee that all sensitive text can be recognized.

## Remaining gates

Offline tests exercise the compiler and expose its semantic limits. They are
not answers generated by a real model. A later integration must compare ordinary
and record-shaped answers on identical source inputs, with the same pinned
model, one generation each and unchanged output ceiling. Include full-source
controls and missing-evidence strata; count malformed/overflow responses and
unnecessary abstention rather than dropping them.

Fresh cases, rubric, operator, accounting and fake-HTTP rehearsals must be frozen
and independently reviewed before another paid comparison. Existing experiment
failures are retained without regeneration. Installed MCP/natural-host behavior,
real user usefulness, package publication and commercial integration remain
separate gates. This candidate changes no production default.
